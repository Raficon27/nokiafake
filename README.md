# NokiaFake — מצב Nokia ל־QIN F21 Pro

פרויקט Android Studio עצמאי. הוא נועד להיפתח כממשק Nokia בעברית בזמן שהפעילות בחזית, ולהיסגר בחזרה ל־Android. הוא אינו Launcher ואינו משתמש ב־Root.

## מצב המימוש

### גרסת ההדגמה וההגדרה

בעת ההפעלה הראשונה מופיע מסך הכנה בעברית: בוחרים מצב פעולה מלאה או דמה, הרשאות מוצגות לפי המצב, וכל שורת הרשאה פותחת את בקשת Android המתאימה. בשני המצבים מתבקשות רק הרשאות התכונות המשותפות: אנשי קשר, יומן שיחות, מצלמה, מדיה, מיקרופון ולוח שנה, וכן הרשאת שכבת־על לחסימת מגע. רק מצב מלא מבקש גם תפקיד ברירת המחדל ל־SMS, קריאת וקבלת SMS, חיוג ושליחת SMS. במצב דמה לא נפתחות הודעות המכשיר; ניתן להזין מספר, לכתוב הודעה ולשלוח אותה כהדמיה מקומית בלבד. הספירה בתחתית מציגה את זמן ההפעלה המצטבר. כל שורת הרשאה והקישור ״אשר הרשאה הבאה״ פותחים את בקשת Android המתאימה; הכפתור העגול מפעיל את מצב Nokia. בלי הרשאת שכבת־על ההפעלה תבקש אותה תחילה. אם נדחו הרשאות אחרות, המסכים התלויים בהן יציגו שאינם זמינים בלי להפיל את האפליקציה. מצב דמה אינו מציין זאת במסך הבית, אך במסכי הפעולות ובהגדרות כתוב במפורש שחיוג ושליחת SMS הם הדמיה. שליחת דמה נשמרת בזיכרון רק לסשן הנוכחי.

התפריט מציג רשת 3×6 עם 17 פריטים, טבעת בחירה כתומה ורקע ירח מצויר בהשראת תמונות Nokia שהמשתמש סיפק. מקשי החצים נעים ברשת; MENU/Soft Left מפעיל את המקש השמאלי, BACK/Soft Right את הימני. בדיקת KeyCode ו־ScanCode זמינה דרך הגדרות > בדיקת מקשים כדי לזהות שינויי קושחה ב־F21 Pro. בהקלדה פנימית: 0 רווח, * סימנים, # מעבר עברית/English/123, חץ ימינה/שמאלה מזיז את הסמן, ומקש מחיקה מוחק. אין שדה EditText או מקלדת מסך.

היציאה מתבצעת באמצעות 1234 בחייגן, או עשר הקשות רצופות בפינה השמאלית העליונה של המסך הגלוי (עד 2.4 שניות בין הקשות). ההקשות נספרות בלחיצה עצמה; אפשר ללחוץ גם מעט מתחת לקצה העליון שהמערכת שומרת למחוות שלה. שכבת־העל בולעת את שאר הנגיעות בחלון שלה.

הפרויקט כולל צילום תמונות עם Preview פנימי ושמירה ל־MediaStore, גלריית תמונות, ניגון וידאו ומוזיקה, פנס, הקלטת שמע לתיקיית האפליקציה, שעון מעורר עם התראה, הצגת אירועי לוח שנה, מונים, מחשבון, Snake ומשחק נינג׳ה פשוט. התפריט כולל גם אנשי קשר, יומן שיחות, הודעות והקבצים שלי. כל המסכים האלה מקבלים מקשי חומרה ומתעלמים ממגע. חיוג ו־SMS אמיתיים פועלים במצב מלא דרך Android; מצב דמה אינו יוזם אותם.

מגבלות ידועות: אין ממשק שיחה נכנסת/פעילה פנימי; צילום וידאו זמין דרך מקש # במסך המצלמה אך הצלחתו תלויה בתמיכת Camera/MediaRecorder של הקושחה; נגן הקבצים מציג קבצים שמופיעים ב־MediaStore ולא כל נתיב פרטי של אפליקציות אחרות; השעון המעורר עשוי להיות לא מדויק אם מערכת Android אינה מאפשרת התראה מדויקת. נדרשת עדיין בדיקה מעשית של חיישני המכשיר, הרשאות ומקשים על QIN F21 Pro. לא הועתקו נכסי קושחה.

## מגבלות Android שאי אפשר לעקוף באפליקציה רגילה

- **תפקיד SMS:** Android מציג אישור מערכת לבחירת אפליקציית SMS ברירת מחדל. האפליקציה מבקשת את התפקיד בעת פתיחה רק אם אינו מוחזק. לאחר שהמשתמש אישר, אין API ציבורי שמאפשר לאפליקציה לבטל את התפקיד כשנסגרת או לגרום למערכת לשאול שוב בכל הפעלה; רק המשתמש או המערכת יכולים לשנותו. התפקיד משפיע גם מחוץ לזמן שהאפליקציה פתוחה.
- **מגע:** Activity מתעלמת ממגע בתוך החלון. שכבת־העל מבקשת `SYSTEM_ALERT_WINDOW` ומנסה לבלוע נגיעות כשהאפליקציה פעילה. Android שומר שליטה בחלונות ובמחוות מערכת מסוימות, ולכן אפליקציה רגילה אינה יכולה להבטיח חסימת Touch מוחלטת בכל ממשק או למנוע יציאה/מעבר לאפליקציה אחרת. אם ההרשאה נדחית, רק מסך האפליקציה עצמו מתעלם ממגע.
- **אישור שכבת־על ב־Android 11:** הכפתור במסך ההכנה פותח את דף הרשאות שכבת־העל של המערכת. ב־Android 11 המערכת מתעלמת מכתובת `package:` ומציגה רשימת אפליקציות; בוחרים בה את **מצב Nokia**, מאשרים וחוזרים לאפליקציה. אין API ציבורי שמדלג על בחירת האפליקציה או מאשר את ההרשאה בשמה. לאחר החזרה המסך מזהה אוטומטית את האישור.
- **סרגל המצב/ההתראות:** האפליקציה מפעילה Immersive Sticky, אך Android מאפשר לחשוף את הסרגל באמצעות מחוות קצה. חלון `TYPE_APPLICATION_OVERLAY` נמצא לפי תיעוד Android **מתחת** לחלונות מערכת קריטיים ובהם שורת המצב; לכן הטריק של פס צף שקוף אינו מספק חסימה מלאה, גם באנדרואיד 11. במכשיר שהוגדר מראש כ־Device Owner, האפליקציה קוראת ל־`DevicePolicyManager.setStatusBarDisabled(true)` עם הכניסה, ומשחזרת `false` ביציאה. זהו מסלול החסימה הרשמי. במכשיר אישי רגיל ללא ניהול מכשיר לא ניתן לאמת או להבטיח חסימה הרמטית של הווילון באמצעות הרשאת Overlay, ולכן מסך ההכנה מציג במפורש שמצב זה דורש ניהול מכשיר.
- **תפקיד SMS במעבר למצב דמה:** מצב דמה אינו מבקש את תפקיד SMS ואינו קורא הודעות קיימות. אם מצב מלא קיבל בעבר את התפקיד, Android אינו מאפשר לאפליקציה להחזירו אוטומטית. המערכת עשויה עדיין למסור לה SMS נכנס; המקלט שומר אותו ב־SMS Provider כדי לא לאבד הודעה, אך ממשק הדמה אינו מציג אותו. יש לבחור מחדש את אפליקציית ה־SMS הרגילה ב־Android אם עוברים לדמה באופן קבוע.
- **שיחות נכנסות:** הצגת ממשק שיחה משלנו דורשת תפקיד Dialer ברירת מחדל ו־Telecom `InCallService`. הפרויקט אינו מבקש את התפקיד הזה, ולכן Android מטפל בשיחות.
- **יציאה:** `1234` בחייגן מסיים את הפעילות. לחצן Back/End מסוגל גם לצאת ממסכים או לסגור פעילות; אפליקציה רגילה לא יכולה לנעול את המשתמש בתוכה באופן אמין בלי מצב ניהול מכשיר ייעודי.

## Build

GitHub Actions בונה APK Debug בכל push ל־`main` וב־workflow ידני. הקובץ נשמר כ־Actions artifact בשם `NokiaMode-debug-apk` למשך 30 יום.

לבנייה מקומית:

1. התקן Android Studio, Android SDK Platform 35 ו־JDK 17.
2. פתח את תיקיית הפרויקט ב־Android Studio והמתן ל־Gradle Sync.
3. בחר **Build > Build APK(s)**. ה־APK ייווצר ב־`app/build/outputs/apk/debug/app-debug.apk`.

במערכת עם Gradle 8.7:

```bash
gradle --no-daemon assembleDebug
```

## התקנה ובדיקה

התקן את `app-debug.apk` ופתח את האפליקציה. בניית Debug ב־GitHub Actions נוצרת עם חתימת Debug מקומית של הרץ; אם Android דוחה עדכון מעל APK Debug קודם בגלל חתימה שונה, יש להסיר את הגרסה הקודמת ולהתקין מחדש (נתוני האפליקציה המקומיים יימחקו). להפצה יציבה דרוש מפתח חתימה פרטי קבוע. מסך ההכנה נפתח לפני מצב Nokia: בחר מצב מלא או דמה, אשר את שורות ההרשאה, גלול ברשימה באמצעות החצים או בהחלקה, ואז הפעל בעזרת הכפתור העגול. מצב דמה אינו מבקש הרשאת SMS ואינו מציג הודעות קיימות. במצב מלא יש לאשר גם תפקיד SMS, קריאת הודעות, חיוג ושליחה. בדוק את כל מקשי F21 Pro בפועל; קודי KeyEvent עשויים להיות שונים בין גרסאות קושחה.

## חסימת וילון במכשיר מנוהל

החסימה המלאה משתמשת ב־Device Owner, בלי Root. הגדרה ראשונית זו נעשית דרך מנגנון ניהול המכשיר של Android, ואינה ניתנת לאישור בלחצן הרשאה בתוך אפליקציה רגילה. במכשיר בדיקה נקי שלא הוגדר עם חשבונות/בעלים אחרים, מנהל המכשיר יכול להתקין את ה־APK ואז לבצע מהמחשב עם ADB:

```bash
adb shell dpm set-device-owner com.example.nokiamode/.NokiaAdminReceiver
```

לא בכל F21 Pro או התקנה קיימת Android יאפשר את הפעולה; ייתכן שתידרש הכנת מכשיר ייעודי לפי הוראות Android Enterprise. אין לבצע איפוס מכשיר בלי גיבוי והחלטת המשתמש. אחרי שהמכשיר מנוהל, מסך ההכנה מציג שחסימת הווילון זמינה, והאפליקציה מפעילה/מבטלת אותה עם כניסה/יציאה. במכשיר לא מנוהל מתבצעת רק הסתרת סרגלים וחסימת נגיעות בחלון האפליקציה, והווילון עשוי להיפתח. לא נבדק פיזית על F21 Pro בסביבה זו.

## MMI_RES

תיקיית `MMI_RES` לא הייתה זמינה בסביבת העבודה בעת יצירת הפרויקט, ולכן לא נבנה inventory ולא הועתקו נכסי Nokia. יש להוסיף אותה לפרויקט לצורך ניתוח ושיפור העיצוב.

## מקורות Android בנושא Immersive ו־Device Owner

- Immersive mode: https://developer.android.com/develop/ui/views/immersive
- הנחיות Android לתוכן Immersive ומגבלת הסתרה קבועה במכשיר אישי: https://developer.android.com/design/ui/mobile/guides/layout-and-content/immersive-content
- `DevicePolicyManager.setStatusBarDisabled`: https://developer.android.com/reference/android/app/admin/DevicePolicyManager#setStatusBarDisabled(android.content.ComponentName,boolean)
- `TYPE_APPLICATION_OVERLAY` וסדר חלונות: https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_OVERLAY
- שינוי בקשת שכבת־על ב־Android 11: https://developer.android.com/about/versions/11/privacy/permissions#system-alert-window
- Lock Task למכשירים ייעודיים: https://developer.android.com/work/dpc/dedicated-devices/lock-task-mode
